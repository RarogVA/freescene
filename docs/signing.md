# Постоянная локальная подпись FreeScene

Для стабильных сборок используется одна постоянная пара сертификат/закрытый ключ. Она позволяет macOS распознавать следующие версии FreeScene по сертификату и идентификатору приложения, вместо меняющегося `cdhash` подписи ad hoc. Это самоподписанный сертификат разработчика: он не заменяет Developer ID, не подтверждает личность разработчика для Gatekeeper и не позволяет пройти нотаризацию Apple. Для общего распространения Apple рекомендует Developer ID.

## Подготовка

На доверенном компьютере сборки один раз выполните:

```sh
python3 tools/sign_freescene.py prepare
```

Команда создаёт отдельную Связку ключей в `~/Library/Application Support/FreeScene Signing/`. Папка имеет права `0700`, файлы Связки ключей, её пароля, сертификата и метаданных — `0600`. macOS может создать внутри служебный файл блокировки `.fl*` только для чтения; он не содержит ключ или пароль и также закрыт внешней папкой. Закрытый ключ остаётся в этой Связке ключей; временные PEM/P12 удаляются. Пароль передаётся служебному процессу через stdin, не попадает в аргументы команд, отчёты или журнал сборки. В приложении и репозитории закрытого ключа и пароля нет.

Существующая или частично подготовленная папка не перезаписывается, новый сертификат автоматически не создаётся. Для переноса сборки на другой компьютер сохраните всю папку в защищённой резервной копии. Потеря или замена ключа требует явной смены идентичности и повторного разрешения доступа к прежним данным Связки ключей.

Проверка публичных сведений:

```sh
python3 tools/sign_freescene.py describe
```

Подготовка не меняет доверие к корневым сертификатам macOS, Связку ключей по умолчанию или список поиска. Доступ к закрытому ключу предоставляется только `/usr/bin/codesign`, без разрешения всем приложениям и без изменения partition list.

## Стабильная сборка

```sh
python3 tools/build_freescene.py --channel stable \
  --vlc-sources /path/to/FreeScene-VLC-sources.tar.gz \
  --destination build/local-stable
```

До запуска Flutter проверяются файлы идентичности, наличие соответствующего закрытого ключа и срок сертификата. Отсутствующая или повреждённая идентичность останавливает сборку; перехода на ad hoc нет. Для отдельной папки используется `--signing-identity-dir`. Локальные Preview-сборки могут сохранять подпись ad hoc.

После сборки сначала подписывается помощник обновления, затем приложение. Их designated requirements привязаны к одному сертификату, но к разным идентификаторам: `local.freescene.freescene` и `local.freescene.freescene.update-helper`. Поэтому подпись помощника сама по себе не даёт ему доступ к данным аккаунтов приложения. Entitlements и флаги кода сохраняются. Проверяются целостность всей подписи и явное выполнение каждого требования через `codesign -R`: одного `codesign --verify` для этого недостаточно.

В `build-result.json` сохраняются только публичный SHA-256 сертификата, требования подписи и признаки отсутствия Developer ID/нотаризации. Установленное пользовательское приложение этот процесс не изменяет.

## Связка ключей и обновления

С 1.3.1 работающее приложение хранит GitHub-токен в локальном профиле и не обращается к Связке ключей. Прежние записи не читаются и не удаляются; токен нужно один раз вставить заново. Инструменты подписи продолжают использовать отдельное приватное хранилище сертификата, описанное выше. Следующий абзац описывает прежнее поведение версий до 1.3.1.

При переходе со старой подписи ad hoc прежние записи могут запросить разовое разрешение для новой идентичности. Стабильная подпись не отменяет этот переход и не обходит согласие пользователя. После разрешения следующих версий с тем же сертификатом macOS может узнавать их по прежнему требованию. Отказ, отмена или необходимость системного диалога не означают, что сохранённый токен отсутствует; запись должна оставаться на месте.

Установщик проверяет требование самого пакета и, для уже подписанного сертификатом приложения, требование установленной версии. Смена сертификата и возврат к ad hoc отклоняются. Переход от прежнего ad hoc к первому сертификату разрешён.

Проверка изолированного сценария:

```sh
python3 tests/native/signing_regression.py
```

Тест подписывает разные временные `.app`, проверяет сохранение доступа к отдельной тестовой Связке ключей между версиями и отказ другому сертификату/идентификатору помощника, сохранение entitlements/флагов и ограничения установщика. Пользовательские записи, системное доверие и установленное приложение не используются.

Основания: [Apple о designated requirements](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements), [язык требований подписи](https://developer.apple.com/library/archive/documentation/Security/Conceptual/CodeSigningGuide/RequirementLang/RequirementLang.html), [создание и ограничения самоподписанной идентичности](https://developer.apple.com/library/archive/documentation/Security/Conceptual/CodeSigningGuide/Procedures/Procedures.html).
